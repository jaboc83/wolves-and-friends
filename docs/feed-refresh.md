# Public feed collection

`lib/feeds/index.ts` registers provider tasks; `lib/feeds/provider-tasks.ts` runs at most six tasks concurrently by default with a 20-second refresh deadline. News-only collections explicitly run all registered tasks concurrently; opponent-injury lookups use five workers and a 12-second deadline. Every provider owns its buffer. Completed results merge in registration order, so response ordering does not depend on network completion. Failed or late results are excluded and reported in source health. Official fixtures retain their merge rules, live scoreboards overlay schedules, and injuries attach after those merges.

`lib/feeds/feed-parsers.ts` contains pure RSS/ESPN parsers, `lib/feeds/feed-types.ts` holds the normalized contracts, and `lib/feeds/news-sources.ts` configures publishers/authors. New providers should use the scoped transport so collection cancellation reaches upstream requests. Shared scoreboards use their independent short-lived cache; one collection timing out must not cancel another caller's shared fetch.

News, schedules and odds have separate per-Worker caches and in-flight requests. These are public data caches, not globally shared storage. The legacy combined endpoint only attempts odds within its remaining refresh budget, using isolated objects so late odds cannot mutate returned schedules. Author verification expires after an hour and holds at most 256 results.

Browser refreshes prioritize the selected page before background work. A team view loads its shared dashboard feeds and `/api/news?team=<team>` first; All Teams uses one unfiltered `/api/news` request, and March Madness loads its bracket first. Remaining team-news requests run sequentially in the background, rechecking the selection before each request; responses stay cached in page state and the per-team server cache. Navigation starts the new page immediately without waiting behind the background queue. Failed visible requests retain their existing fallback behavior and release the queue. Team selection stays in localStorage and is included only as a filter on team-news requests. Read/saved state is not sent, and no separate tracking request is used.

Roster-stat requests run two batches at a time, with an independent 20-second timeout for each request so slow early batches do not prevent later players from loading. HTTP 409 manifest conflicts invalidate the browser's manifest and batch indexes; the next retry fetches the current manifest while retaining already displayed stats.

Separate salary lookups use `/api/roster-salaries?team=<team>` after roster stats settle and the browser is idle, with a delayed fallback if stats remain pending. Wolves annual pay comes from SalarySwish; Wild annual cash pay comes from CapWages contract details for the requested season, including signing bonuses rather than cap hit or AAV. Twins figures use FanGraphs RosterResource's published annual `Salary` (including allocated signing bonuses), not AAV, estimates, or future options. MLB uses a calendar-year season and the source request/link explicitly selects that year; players without published figures stay blank. Crystal Palace uses SalarySport's reported yearly basic wages in GBP, excluding bonuses; the parser requires the requested season's squad table and GBP source currency, never substitutes weekly wages, and leaves unmatched players blank. Lynx figures use Her Hoop Stats' published 2026 salary-cap sheet in USD; Frost figures use the PWHLPA's published 2025-26 guide and are labeled as potentially different from current contracts. Frost roster names, positions, and ages come from the current-season PWHL official stats feed; it does not fall back to the dated training-camp announcement. Palace amounts display in pounds without currency conversion; existing US-team amounts remain in dollars. These server-only lookups use configured public team URLs, never visitor headers or forwarded filters. Public salary values are cached for 15 minutes on the server and 12 hours in localStorage and stay visible while refreshing; stale/error states are shown explicitly.

Preserve local preference storage, same-origin credentials-omitted/no-referrer feed calls, independent section completion, safe source-health codes and no stale seed headline injection. Send non-identifying sports filters only when useful; never persist or log them remotely, or forward them to third parties. Scheduling is covered by `tests/page-first-feeds.test.ts`, team news URL construction by `tests/news-page-data.test.ts`, and injury normalization by `tests/feed-injuries.test.ts`; run the Node suite with `pnpm test`.
