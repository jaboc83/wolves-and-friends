# Public feed collection

`lib/feeds/index.ts` registers provider tasks; `lib/feeds/provider-tasks.ts` runs at most six tasks concurrently by default with a 20-second refresh deadline. News-only collections explicitly run all registered tasks concurrently; opponent-injury lookups use five workers and a 12-second deadline. Every provider owns its buffer. Completed results merge in registration order, so response ordering does not depend on network completion. Failed or late results are excluded and reported in source health. Official fixtures retain their merge rules, live scoreboards overlay schedules, and injuries attach after those merges.

`lib/feeds/feed-parsers.ts` contains pure RSS/ESPN parsers, `lib/feeds/feed-types.ts` holds the normalized contracts, and `lib/feeds/news-sources.ts` configures publishers/authors. New providers should use the scoped transport so collection cancellation reaches upstream requests. Shared scoreboards use their independent short-lived cache; one collection timing out must not cancel another caller's shared fetch.

News, schedules and odds have separate per-Worker caches and in-flight requests. These are public data caches, not globally shared storage. The legacy combined endpoint only attempts odds within its remaining refresh budget, using isolated objects so late odds cannot mutate returned schedules. Author verification expires after an hour and holds at most 256 results.

Browser refreshes prioritize the selected page before background work. Team views load shared dashboard feeds and the generic `/api/news` response first; the browser partitions that response into team pages locally. All Teams treats all team pages as visible content; March Madness loads its bracket first. Remaining news pages populate sequentially from the fetched response, rechecking the selection before each step. Navigation starts the new page immediately without waiting behind the background queue. Failed visible requests retain their existing fallback behavior and release the queue. Selection stays in localStorage; the current news request does not send it. If useful for filtering, a first-party request may include non-identifying sports preferences, but never as a tracking request, remote stored preference, or third-party parameter.

Preserve local preference storage, same-origin credentials-omitted/no-referrer feed calls, independent section completion, safe source-health codes and no stale seed headline injection. Send only non-identifying sports filters when useful; never persist or log them remotely, or forward them to third parties. Scheduling is covered by `tests/page-first-feeds.test.ts`, local news partitioning by `tests/news-page-data.test.ts`, and injury normalization by `tests/feed-injuries.test.ts`; run the Node suite with `pnpm test`.
